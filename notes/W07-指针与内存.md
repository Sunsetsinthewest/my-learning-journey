## 指针

- 指针是**存地址的变量**；指针自己也有地址（`&p`），而且和它指向的变量地址不同
- `int* p = &x;`：`p` 的值是 x 的地址，`*p` 是 x 那一格，改 `*p` 就是改 x
- `*` 在声明里是类型的一部分（`int* p`），在表达式里是解引用（`*p = 5`）
- 64 位系统里指针占 8 字节，**和它指向什么类型无关**；类型决定的是「读几字节、加 1 走多远」

## 指针与数组

- `a == &a[0]`；`a[i]` 就是 `*(a + i)`，方括号只是语法糖
- `p + 1` 走 `sizeof(指向类型)` 个字节：`int*` 走 4、`double*` 走 8、`char*` 走 1
- 两个指针相减得到「隔了几个元素」，不是字节数
- **数组传参传的是指针**：`void f(int arr[])` 和 `void f(int* arr)` 是一回事
- 所以函数里 `sizeof(arr)` 失效（8 而不是 20），必须把长度或 `end` 一起传进去
- `[begin, end)` 半开区间：`end` 指向最后一格的**后面**，空区间天然安全

## const 与指针

| 写法 | 能不能改数据 | 能不能改指向 |
| --- | --- | --- |
| `const int* p` | 不能 | 能 |
| `int* const p` | 能 | 不能 |
| `const int* const p` | 不能 | 不能 |

口诀：`const` 在 `*` 左边锁数据，在 `*` 右边锁指针。

## 三种交换

- **值传递**：改的是副本，函数里换得再热闹，外面不变
- **引用传递**：改的是本体，调用时不用加 `&`
- **指针传递**：传地址，调用时要 `&`，能表达「这个参数可能为空」
- **指针本身也是按值传递**：`void f(int* p) { p = nullptr; }` 改不了调用者的指针，只能改它指向的东西

## 空指针与野指针

- 野指针：`int* p;` 没初始化，里面是垃圾地址
- 空指针：`int* p = nullptr;`，明确不指向任何地方，解引用必崩（访问 0 号地址）
- 悬垂指针：指向的变量已经销毁，地址还留着；**经常读到旧值、程序不崩**，最危险
- 防御：声明即初始化、解引用前判空、不返回局部变量的地址

## 踩过的坑（W07 验收实测）

- **`maxByPointer` 少了 `if (*p > *pMax)`** —— 循环里每轮都无条件 `pMax = p`，返回的其实是**最后一个元素**。样例 `3 1 4 1 5` 最后一个是 5，刚好是最大值，所以样例能过；全负数 `-5 -2 -9 -7` 输出 `-7`，正确答案是 `-2`。**样例通过不等于逻辑对。**
- **`swap3` 第 ④ 行打印错了变量** —— 应该打印第四组（现在叫 `nullA / nullB`），却写成了第三组（`ptrA / ptrB`），所以第四行显示 `x = 2，y = 1`。编译器警告 `unused variable 'h'`（当时那一组叫 `g / h`）就是线索：变量声明了却没用到，八成是这里写错了。
- **行末多余空格** —— `printByPointer` 每个数后面都跟一个空格，最后一个后面也多一个。改成「不是第一个才先输出空格」。
- **输出格式要逐字符对齐** —— `x=1` 和 `x = 1` 是两回事；`result 仍是42` 少一个空格，和模板对不上。
